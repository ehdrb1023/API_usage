# `client-keys.json` — 서비스별 사용량 표의 표시 이름

대시보드 Claude 탭의 **"서비스별 사용량"** 표에서 각 줄에 어떤 이름을 띄울지
팀이 직접 정하는 파일입니다. 코드 수정 없이 이 파일만 고치면 됩니다.

```json
{
  "apikey_01CUM5RWcLMP5RdrL6LSt8gV": "○○법무법인 챗봇",
  "apikey_018PUjgp8bomUGc1o3peK1oR": "△△ 마케팅 자동화"
}
```

`{ "api_key_id": "표시할 이름" }` 형태의 단순 객체입니다. JSON 이라 주석을 넣을 수 없어서
설명은 이 파일에 둡니다.

## api_key_id 는 어디서 확인하나

**api_key_id는 Console → API 키 페이지에서 키 이름 옆 점 3개 메뉴 → 세부정보에서 확인
가능합니다. 또는 대시보드 화면에 회색으로 표시된 앞자리로 어떤 키인지 유추 가능합니다.**

## 이름을 정하는 우선순위

표의 이름은 아래 순서로 정해집니다.

| 순위 | 출처 | 언제 쓰이나 |
|---|---|---|
| 1 | **이 파일의 매핑** | `api_key_id` 가 이 파일에 있으면 무조건 이 이름 |
| 2 | Console 에 등록된 키 이름 | 이 파일에 없을 때 |
| 3 | 키 앞자리 (`apikey_01CUM5RW…`) | Console 목록에도 없는 키 (삭제됐거나 다른 조직) — `미등록` 배지가 붙습니다 |

## 알아 둘 것

- **이 파일이 비어 있어도(`{}`) 대시보드는 지금까지와 똑같이 동작합니다.** 전부 2순위,
  즉 Console 키 이름으로 표시됩니다.
- **여기 없는 키는 지워지지 않습니다.** 매핑은 이름만 바꿀 뿐, 어떤 줄도 표에서 빼지 않습니다.
- **이름이 겹치면 키 앞자리가 옆에 회색으로 붙습니다.** 서로 다른 거래처에 같은 이름을
  붙이면 표에서 구분이 안 되므로, 이름은 거래처마다 다르게 정하는 편이 좋습니다.
  (실제로 Console 에는 `speciai.team` 이라는 이름의 키가 두 개, `marketing` 계열 변형이
  다섯 개 있습니다. 이 파일로 정리하기 좋은 대상입니다.)
- **저장하면 바로 반영됩니다.** 대시보드가 요청마다 이 파일을 다시 읽으므로 서버를
  재시작할 필요가 없습니다.
- **JSON 문법이 틀리면 매핑 전체가 무시되고** 2순위(Console 이름)로 되돌아갑니다.
  화면은 멀쩡해 보이는데 이름만 안 바뀐다면, 서버를 띄운 터미널에 찍힌
  `[client-keys]` 경고를 확인하세요.
- 이 파일은 **커밋 대상**입니다. 키 값(비밀)이 아니라 키 **식별자**와 표시 이름만
  들어가므로 저장소에 두고 팀이 함께 관리합니다.
